3Accept–Reject (AR) method

The fallback when F⁻¹ has no closed form: propose from an easy distribution g, keep the draw with probability f(x)/(c·g(x)).

3.1Setup and the envelope constant

Pick a proposal density g(x) that's easy to sample from, and find a constant c such that:

f(t)g(t) ≤ c   for every t where f(t)>0

i.e. c = maxt f(t)/g(t). Smaller c ⇒ fewer rejections ⇒ more efficient — this is the whole game when comparing two candidate proposals.

3.2Algorithm

  1. Draw Y ∼ g.
  2. Draw U ∼ Uniform[0,1].
  3. If U < f(Y)/(c·g(Y)), accept and return X=Y. Otherwise reject and go back to step 1.
Why it works, in one line — P(accept|Y=y)=f(y)/(c·g(y)), so P(Y=y|accept) ∝ g(y)·f(y)/g(y) = f(y) — the g(y) cancels exactly, which is precisely why it must appear in the denominator of the test. Overall P(accept)=1/c, so the number of proposals needed until one is accepted is Geometric with expectation c — the direct reason a smaller c means a faster algorithm.

3.3Worked example — uniform proposal

f(x) = 6x(1−x), 0≤x≤1 (a Beta(2,2)). Use g(x)=1 on [0,1] (Uniform).

f′(x)=6(1−2x)=0 ⇒ x=0.5 is the maximum, f(0.5)=1.5

c = max f(x)/g(x) = 1.5/1 = 1.5

Accept Y∼Unif(0,1) if U < f(Y)/1.5 = 4Y(1−Y)

3.4Worked example — non-uniform proposal (ratio simplifies)

f(x) = 20x(1−x)³, 0≤x≤1 (Beta(2,4)) — use the Beta(2,2) density g(x)=6x(1−x) from §3.3 as the proposal instead of Uniform. The x terms cancel, which is the whole point of picking a proposal shaped like f:

f(x)g(x) = 20x(1−x)³6x(1−x) = 103(1−x)²  — maximized as x→0, giving c = 10/3 ≈ 3.333
Note — with a non-uniform proposal the ratio f(x)/g(x) genuinely depends on x; you cannot skip computing it, unlike the special case in §3.6.

3.5Two more fully-worked past-exam setups

v23 — truncated normal. f(x)=C·e−x²/2 on [−2,2], C≈0.41796 (normalizing constant for a standard normal truncated to [−2,2]). With g(x)=1/4 (Uniform(−2,2)):

max of e−x²/2 on [−2,2] is at x=0, value 1  ⇒  c = C/(1/4) = 4C ≈ 1.672

v26. f(x)=(1+sin x)/(π+2) on [0,π] — no closed-form inverse (§2.2), so AR with g(x)=1/π (Uniform(0,π)):

max of 1+sin x on [0,π] is at x=π/2, value 2  ⇒  c = 2/(π+2)1/π = 2ππ+2 ≈ 1.222

Also seen (design-the-algorithm only, no numbers given): v24 Beta(2,2) — same setup as §3.3 · v25 Beta(2,4) via Beta(2,2) — same setup as §3.4

3.6Spot-the-bug — h22

f(x)=(1/4C)ex/4 on [0,4], C=e−1, proposal Uniform(0,4) so g(x)=1/4 and c=4·f(4). Do both functions return correct AR samples?

p1.ar.1 <- function(){
  c <- 4.0*p1.pdf(4.0)
  while(TRUE){
    x <- runif(1, min=0, max=4)
    if(runif(1) < p1.pdf(x)/(c*dunif(x, min=0, max=4))){ return(x) }
  }
}
p1.ar.2 <- function(){
  c <- 4.0*p1.pdf(4.0)
  while(TRUE){
    x <- 4.0*runif(1)
    if(runif(1) < p1.pdf(x)/c){ return(x) }
  }
}
Both are statistically correct — but not equally efficient.

p1.ar.1 implements the textbook test U < f(x)/(c·g(x)) exactly, since dunif(x,0,4)=1/4=g(x). p1.ar.2 tests U < f(x)/c instead — it silently drops the g(x) factor. Because g(x)=1/4 is constant here, this only rescales every acceptance probability by the same factor 4 (concretely, p1.ar.2's test value is exactly 1/4 of p1.ar.1's, for every x) — and scaling a valid acceptance probability by a constant never changes which x's get accepted relative to each other, only how often anything gets accepted. So p1.ar.2 samples from the correct f, it just needs on average 4× more proposals per accepted draw (efficiency c/k with k=1/4, vs. efficiency c for p1.ar.1).

This shortcut is fragile — it only works because g happens to be constant (a uniform proposal). With any non-uniform proposal (§3.4's Beta(2,2) proposal, or v23's truncated-normal proposal), omitting g(x) from the denominator does bias the accepted sample toward wherever g is smallest — that would be a genuine correctness bug, not just an efficiency loss. Always divide by g(x); treat "it still works without it" as a special-case curiosity, not a technique to rely on.

3.7Choosing between proposals (efficiency)

v23 gives two candidate proposals for the same f and asks which is preferable. Since E[proposals needed]=c, the answer is always: compute (or estimate) c for each candidate and pick the smaller one — a proposal that hugs the shape of f more closely (as in §3.4) beats a flat uniform proposal (as in §3.3) whenever f is far from flat itself.
