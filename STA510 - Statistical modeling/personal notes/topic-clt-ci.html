2.1Laws of large numbers (why simulation works at all)

For iid X₁,…,Xn with E(X)=μ:

Xn → μ as n→∞ (weak: in probability; strong: almost surely)

This is the one-line justification for every Monte Carlo estimator in the course: an average of simulated draws converges to the true expectation.

2.2The Central Limit Theorem

For iid X₁,…,Xn from any distribution with mean μ and variance σ²:

Z = X − μσ/√n ≈ N(0,1)   ⇔   Z = ΣXi − nμ√(nσ²) ≈ N(0,1)

Same statement whether you're standardizing an average or a sum — pick whichever matches the question. Rule of thumb: the approximation is generally fine once n≥30.

The one formula behind every CI in this course: Z = (θ̂ − E(θ̂))/SD(θ̂) ≈ N(0,1) for any estimator that is itself an average (a sample mean, a Monte Carlo estimator, a relative frequency, …). Everything below is this same formula rearranged.

2.3Confidence interval for a mean

X ± zα/2·σ/√n

with σ replaced by the sample sd s when unknown (as is almost always the case in this course).

2.4Sample size for a target precision

Rearranging the CI so the margin of error is at most e:

zα/2·σ/√n < e  ⇒  n > z²α/2σ²/e²   (95%: n > 4σ²/e², since z0.025≈1.96≈2)

Since σ is usually unknown ahead of time: run a moderate pilot simulation/sample to estimate it, then plug the estimate into the formula for the real run.

2.5Estimating a probability specifically

A relative frequency p̂ = (#successes)/n is itself an average of 0/1 indicators, so everything above applies with Var(p̂) = p(1−p)/n:

CI: p̂ ± zα/2√(p̂(1−p̂)/n)  ·  n > z²α/2p(1−p)/e²

Since p(1−p) ≤ 0.25 always, a universal (conservative) bound at 95% confidence is:

n > 1/e²  (95%, using p(1−p)=0.25 and z≈2)
Don't confuse the sd of individual draws with the sd of the estimator. If a question asks for n such that SD(p̂) < e directly (no z involved), solve √(p(1−p)/n) < e — don't add a z-multiplier unless the question is about a CI margin. See the worked contrast on the Monte Carlo integrals page.

2.6Spot-the-bug — matching point estimate to standard error (h22)

Target θ=E(√X). Three candidate point estimates and six candidate 95% CIs:

point.1 <- mean(sqrt(x))          # mean of the transformed variable
point.2 <- sqrt(mean(x))          # sqrt of the mean  -- NOT the same thing!
point.3 <- mean(sqrt(x>0))        # sqrt(x>0) is just (x>0) as 0/1 -- degenerate

CI.1 <- point.1 + c(-1,1)*1.96*sd(x)/sqrt(n)          # wrong sd
CI.2 <- point.1 + c(-1,1)*1.96*sd(sqrt(x))/sqrt(n)    # matches!
CI.3 <- point.2 + c(-1,1)*1.96*sd(x)                  # missing /sqrt(n)
CI.4 <- point.2 + c(-1,1)*1.96*sqrt(sd(x))/sqrt(n)    # nonsense sqrt(sd(x))
CI.5 <- point.3 + c(-1,1)*1.96*sd(sqrt(x))             # missing /sqrt(n)
CI.6 <- point.3 + c(-1,1)*1.96*sd(sqrt(x))/n           # /n instead of /sqrt(n)
point.1 is the unbiased estimator — it's literally the sample mean of √X, which is exactly θ=E(√X). point.2 estimates √E(X) instead (biased for θ by Jensen's inequality, since √· is concave). point.3 is degenerate — since X>0 always on its support, it just estimates P(X>0)=1. Only CI.2 is valid: it's the only one pairing the correct point estimate (point.1) with the correctly-transformed standard error (sd(sqrt(x))/sqrt(n)) — every other CI either uses the wrong variable's sd, forgets to divide by √n, or divides by n instead.
The general lesson: whenever a question estimates E(g(X)) for some transformation g, the standard error must come from sd(g(X)), never from sd(X) — the two are only equal when g is the identity.

2.7Worked example — sum of dice

Throw a fair die 50 times; what's P(sum > 200)? Each throw Xi has E(Xi)=3.5, Var(Xi)=35/12≈2.917 (discrete uniform on 1–6). With n=50, CLT applies to Y=ΣXi:

E(Y)=50(3.5)=175,  SD(Y)=√(50×2.917)≈12.07
P(Y>200) = P(Z > (200−175)/12.07) = P(Z>2.07) ≈ 0.019

2.8Worked example — sample size for a simulation (robot system)

Reusing the robot-system lifetime from the Reliability page: a pilot run of 1000 simulations gives s≈4 (months). How many simulations are needed to estimate the mean lifetime to within e=1 month, and to within one day (e=1/31 month), both at 95%?

One month: n > 4s²/1² = 4(16) = 64 (rounds up in practice to a few thousand once simulation is this cheap)

One day: n > 4s²/(1/31)² = 4(16)(961) ≈ 61{,}500

Tightening the precision by a factor of 31 costs roughly 31²≈961 times more simulations — the 1/√n wall, made concrete.

2.9Common exam pitfalls

  • When several candidate CI expressions are given in R, check that the point estimate and the standard error in the numerator and denominator actually match — see the full h22 bug-spotting walkthrough in §2.6.
  • Know both directions of the CLT (average form and sum form) — a question may hand you per-item mean and variance and ask about the total.
  • Sample-size formulas always come from solving the CI margin for n — don't memorize the final formula blindly, re-derive it if unsure which constant goes where.
