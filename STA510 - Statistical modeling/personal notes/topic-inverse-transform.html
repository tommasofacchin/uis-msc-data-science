2.1The theorem and why it works

If X has cdf F, then U = F(X) ∼ Uniform[0,1].

Turning this around: draw U ∼ Uniform[0,1] and set X = F⁻¹(U). Proof that this gives the right distribution:

P(X ≤ x) = P(F⁻¹(U) ≤ x) = P(U ≤ F(x)) = F(x)
Useful symmetry — since U ∼ Uniform[0,1] implies 1−U ∼ Uniform[0,1] too, F⁻¹(U) and F⁻¹(1−U) are equally valid simulators of X — both are "correct answers" on an exam even though they look different. This is exactly why the exponential inverse is sometimes written −λ⁻¹ln(U) and sometimes −λ⁻¹ln(1−U).

2.2Algorithm

  1. Derive F(x) from f(x), then solve F(x)=u for x to get F⁻¹(u).
  2. Generate u ∼ Uniform[0,1] (in R: runif(1), or runif(n) for a whole vector).
  3. Return x = F⁻¹(u).

Discrete version: with possible values x₁<x₂<…, generate u and return X=xi where F(xi−1) < u ≤ F(xi). In R never hand-roll this — use sample(x, size=n, replace=TRUE, prob=probs).

When it's impossible — if F(x)=u can't be solved in closed form for x (a transcendental equation), inverse transform is off the table and you fall back to Accept–Reject. v26 tests exactly this: for f(x)=(1+sin x)/(π+2) on [0,π], F(x)=(x−cos x+1)/(π+2) — setting this equal to u leaves x tangled up with cos x, with no algebraic way to isolate it.

2.3Worked example — exponential

f(x)=λe−λx, x>0 ⇒ F(x)=1−e−λx

Solve 1−e−λX=U:   X = −λ⁻¹ ln(1−U)  (equivalently −λ⁻¹ ln(U), see the symmetry note above)

2.5Spot-the-bug — v23, f(x)=3√x/16 on [0,4]

True inverse: F⁻¹(u) = 4u2/3. Four candidate R functions — which one is correct?

p1.inv.1 <- function(n){ (3/16)*sqrt(runif(n)) }
p1.inv.2 <- function(n){ 4*runif(n,max=4)^(2/3) }
p1.inv.3 <- function(n){ 4*runif(n)^(2/3) }
p1.inv.4 <- function(n){ (1/8)*runif(n)^(3/2) }
Answer — only p1.inv.3 is correct.

p1.inv.1 reuses the density's own constants instead of the derived inverse — a different formula entirely. p1.inv.2 draws U from runif(n, max=4), i.e. Uniform(0,4) instead of Uniform(0,1) — wrong support for U even though the exponent and outer constant match. p1.inv.4 has both the wrong exponent (3/2 instead of 2/3) and the wrong constant. p1.inv.3 is 4·runif(n)^(2/3), exactly 4U2/3.

2.6Spot-the-bug — h24, Pareto(a=4, b=2)

True inverse: F⁻¹(u) = 4/(1−u)1/2 = 4/√(1−u). Four candidates:

r.pareto1 <- function(n){ 4/sqrt(runif(n,2,4)) }
r.pareto2 <- function(n){ 4/sqrt(runif(n)) }
r.pareto3 <- function(n){ 4/sqrt(1-runif(n)) }
r.pareto4 <- function(n){ 2/(1-runif(n)^(1/4)) }
Answer — r.pareto2 AND r.pareto3 are both correct (this is the "two right answers" trap — don't reflexively pick just one).

r.pareto3 matches the derivation literally: 4/√(1−U). r.pareto2 uses 4/√U — since U and 1−U share the same Uniform[0,1] distribution, this is the same symmetry trick as in §2.1 and produces draws from the identical distribution. r.pareto1 draws U from Uniform(2,4) — wrong support. r.pareto4 has the wrong constant (2 instead of 4) and the wrong exponent (1/4 instead of 1/2) — wrong on two counts at once.

2.7Common exam pitfalls

  • Given several candidate R snippets, check three things independently: the constant out front, the exponent, and the runif interval — a snippet can get two of three right and still be wrong.
  • Remember the U vs 1−U symmetry before declaring a variant "wrong" — it may just be the equivalent form.
  • When asked to "describe the algorithm in words, not code" (a recurring exact phrasing), write the three numbered steps above — don't just paste R.
  • Always double-check the support of X after inverting — e.g. Pareto needs X>a, which a/(1−U)^{1/b} automatically satisfies since (1−U)^{1/b}∈(0,1).
