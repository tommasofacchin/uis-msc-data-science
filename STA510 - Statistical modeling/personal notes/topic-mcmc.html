14MCMC — Metropolis-Hastings

When you can evaluate a target density only up to an unknown constant, build a Markov chain whose stationary distribution is that target — the constant cancels out of every acceptance ratio.

14.1The problem MCMC solves

You know a target density only as π(θ)=g(θ)/C, where g is computable but the normalizing constant C=∫g(θ)dθ is not (typically because θ is high-dimensional). MCMC builds a Markov chain whose stationary distribution is exactly π, using only g — C cancels out of every ratio g(θ*)/g(θt−1) automatically.

14.2Random-walk Metropolis-Hastings (RWMH)

  1. Propose θ* ∼ N(θt−1, Σ) (symmetric around the current state).
  2. Compute α = min(1, g(θ*)/g(θt−1)).
  3. Draw u∼Unif(0,1); if u<α move to θ*, else stay at θt−1.
Tuning — accept rate around 20–40% is the standard target for moderate dimension. Too small Σ: high acceptance but the chain barely moves (slow exploration). Too large Σ: most proposals land where g is tiny, low acceptance, chain gets stuck.

14.3General Metropolis-Hastings & the independence sampler

For an asymmetric proposal q(θ*∣θt−1), the acceptance ratio must correct for the proposal's own asymmetry:

α = min(1, q(θt−1∣θ*)g(θ*)q(θ*∣θt−1)g(θt−1))

RWMH is the special case q(θt−1∣θ*)=q(θ*∣θt−1) (symmetric), so those terms cancel. The independence sampler is the opposite special case: q(θ*∣θt−1)=r(θ*) doesn't depend on the current state at all:

α = min(1, g(θ*)/r(θ*)g(θt−1)/r(θt−1))

Same idea as importance sampling — r should hug g's shape — but the goal now is a good sample, not a good integral.

14.4Spot-the-bug — recognizing the sampler from R code

v23 gives an independence-sampler implementation directly:

x.prop  <- runif(1, min=-2, max=2)              # <- doesn't depend on x[t-1]!
wt.prop <- C*exp(-0.5*x.prop^2) / dunif(x.prop, -2, 2)
wt.old  <- C*exp(-0.5*x[t-1]^2) / dunif(x[t-1], -2, 2)
alpha   <- min(1, wt.prop/wt.old)
Independence sampler. The tell: x.prop is drawn from runif(-2,2) with no reference to x[t-1]. The wt.old/wt.star-style weight ratio (g/r at the proposal, divided by g/r at the current state) is the exact signature of §14.3's independence-sampler ratio — whenever you see this "importance-weight" naming pattern in R, that's the giveaway, regardless of the specific target.

h22 gives the RWMH signature instead — proposal does reference the previous state, and the ratio has no separate proposal-density term:

x.prop <- x[t-1] + 3*rnorm(1)                    # <- centered on x[t-1]
alpha  <- min(1, dnorm(x.prop,mean=2,sd=2) / dnorm(x[t-1],mean=2,sd=2))
Proposal: N(xt−1, 3²). Target: N(2,2) (read off the dnorm arguments). Since it's RWMH, the chain's draws are autocorrelated — an average of the last 500 draws has larger SD than an average of 500 truly iid target draws would, because correlated samples carry less independent information (this is exactly the ESS gap in §14.6).

14.5Spot-the-bug — log-posterior kernel construction

h23: target posterior ∝ L(θ)·p(θ) with prior θ∼Gamma(a=15, b=1/20) (scale b). Recall from §14.7's distribution-recognition table: a Gamma log-kernel must look like const + (a−1)log(θ) − θ/b. Four candidate log-prior lines:

Option1: dgamma(theta, shape=a, scale=b, log=TRUE)     # built-in, correct
Option2: logc1 + n*log(theta) - c2*theta               # manual likelihood kernel, correct form
Option3: log(theta^(a-1)) - log(theta/b)                # BUG
Option4: (a-1)*log(theta) - theta/b                     # correct Gamma kernel
Option 3 is the bug. Expand it: log(θa−1) − log(θ/b) = (a−1)log(θ) − log(θ) + log(b) = (a−2)log(θ) + const — the linear-in-θ decay term −θ/b has vanished entirely. Without it the "density" doesn't decay at all as θ→∞ and isn't normalizable — not a Gamma, not a proper density of any kind. Options 1, 2, and 4 all correctly reduce to the (a−1)log(θ)−θ/b template.

14.6Diagnostics: burn-in, ESS, acceptance rate

Burn-in: discard early samples before the chain has "forgotten" its start — check via trace plot.

ESS (effective sample size): how many iid draws would give the same precision as your T correlated ones. Rule of thumb: want ESS>200; if ESS/T<0.01, something is wrong.

CI for E(θ): θ ± zα/2·SD(θ)/√ESS  (not √T — see the Markov chains page §9.5)
h24 reports a RWMH chain with acceptance rate 0.67 and ESS=15.73 out of 1000 iterations (ESS/T≈1.6%) — a strong red flag despite a seemingly reasonable acceptance rate. High acceptance with very low ESS usually means the proposal steps are too small: the chain accepts almost everything but barely moves, so consecutive draws are nearly identical (highly autocorrelated). Fix: increase the proposal spread, run longer, or thin.

14.7The Gibbs sampler

Split θ=(θ⁽¹⁾,θ⁽²⁾,…) into blocks; cycle through sampling each block from its full conditional given all the others — each conditional is exact, no accept/reject step needed when it has closed form:

  1. Update θ⁽¹⁾ ∼ π(θ⁽¹⁾∣θ⁽²⁾t−1).
  2. Update θ⁽²⁾ ∼ π(θ⁽²⁾∣θ⁽¹⁾t).
  3. Repeat — this preserves the joint target distribution.

Find each conditional by reading off the shape of log g as a function of one block only (everything else fixed) — the recognition table:

log-kernel shapedistribution
a+bx+cx²N(−b/2c, −1/2c)
a+bxExp(−1/b)
a+b·log(x)+cxGamma(b+1, −1/c)
a+b·log(x)+c·log(1−x)Beta(b+1, c+1)
a+b·log(x)−c/xInverseGamma(−(b+1), c)
v25/v26 both ask you to describe the Gibbs algorithm and to give efficiency tips: make blocks as large as possible (update a whole multivariate-normal block at once rather than coordinate-by-coordinate), keep strongly-correlated variables in the same block, and reserve low-dimensional Metropolis steps (a "Metropolized Gibbs sampler") for whichever conditional has no closed form.

14.8Worked example — Normal mean & precision (classic Gibbs)

yi∣μ,τ ∼ N(μ,τ⁻¹), priors μ∼N(0,10²), τ∼Gamma(1,1). Reading the log-posterior kernel's shape in each variable separately:

μ∣τ,y ∼ N(τΣyinτ+1/100, 1nτ+1/100)  (quadratic in μ ⇒ Normal)

τ∣μ,y ∼ Gamma(n2+1, 1S²/2+1),  S²=Σ(yi−μ)²  (a+b log(τ)+cτ shape ⇒ Gamma)

A big, intractable joint posterior reduces to two trivial-to-sample conditionals — this is exactly the pattern v24 and v26 test with a Gamma-Gamma pair and a Normal-Normal/log-Normal-variance model respectively.

14.9Worked example — when RWMH breaks on a constrained parameter

h25: target β>0 with posterior kernel log g(β)=(a₀−n−1)log(β) − β/b₀ − ΣXi/β. A naive RWMH with β* ∼ N(βt−1, σ²) reports acceptance 37% and ESS≈4089 (out of 20000) — numbers that look reasonable, yet the sampler is flawed: a symmetric normal proposal on an unconstrained scale will regularly propose β*<0, invalid for this target. Two standard fixes:

Log-scale proposal: log(β*) = log(βt−1) + ε, ε∼N(0,σ²) — always positive, but now q is asymmetric on the β-scale, so the acceptance ratio needs a Jacobian correction (extra factor β*/βt−1).

Independent Gamma proposal centered on the MLE β̂: match the Gamma's mean to β̂ and its variance to the estimated Var(β̂), then use the independence-sampler ratio from §14.3.
This is exactly why the roadmap flags "remember the Jacobian term" for log-scale proposals — forgetting it silently biases the stationary distribution even though the chain still looks fine on a trace plot.

14.10Common exam pitfalls

  • Recognize the sampler from the proposal line alone: does it reference the current state (RWMH/Gibbs) or not (independence sampler)?
  • Any time a parameter has a hard constraint (positivity, an interval), a plain symmetric-normal RWMH on the natural scale is suspect — expect a log-transform or a matched-support proposal instead.
  • Good-looking acceptance rate ≠ good sampler — always check ESS too.
  • For Gibbs, derive each conditional by isolating the terms of log g that involve that block; everything else folds into an irrelevant constant.
