10.1Series and parallel systems

Series (fails when the first component fails): S = min(X₁,…,Xn)
Parallel (fails only when every component has failed): S = max(X₁,…,Xn)

Simulating either is immediate: draw each component's lifetime independently, then take the min/max — no new distribution theory needed, just combine draws.

10.2The Exponential-as-Weibull shortcut

Exponential(rate α) is Weibull with shape parameter 1. h23 exploits this directly: a series system S=min(X₁,X₂,X₃) with X₁,X₂ iid Weibull(α,β) and X₃∼Exponential(mean=1/α) — recognizing X₃ as a Weibull with the same α and shape 1 lets you simulate all three components with one consistent Weibull inverse-transform formula (see the Inverse transform page, §2.4) instead of two different derivations.

10.3Fully worked example — robot assembly line

System fails when robot 1, robot 2, robot 3, or the rest of the line fails — a series system, T=min(R₁,R₂,R₃,A):

R₁∼Gamma(16,1),  R₂∼Gamma(16,1),  R₃∼Gamma(12,2),  A∼Lognormal(2.3,1.1)  (months) 
gensystemfailuretimes <- function(Nsim){
  R1 <- rgamma(Nsim, shape=16, scale=1)
  R2 <- rgamma(Nsim, shape=16, scale=1)
  R3 <- rgamma(Nsim, shape=12, scale=2)
  A  <- rlnorm(Nsim, meanlog=2.3, sdlog=1.1)
  pmin(R1, R2, R3, A)   # vectorized min -> system lifetime
}

Every question about this system — P(T<12), quantiles, mean lifetime, a histogram/ecdf/density estimate of T — is answered by simulating many T's with this one function and summarizing, exactly the crude-Monte-Carlo pattern from the MC integrals page.

10.4How many simulations? (real numbers)

A pilot run of 1000 draws gives s≈4 months. Using the sample-size formula from the CLT & CIs page:

Mean, precision 1 month: n > 4s²/1² = 64
Mean, precision 1 day (e=1/31 month): n > 4s²/(1/31)² ≈ 61{,}500

Probability of failure within a year, precision 0.05: n > 1/0.05² = 400
Same, precision 0.005: n > 1/0.005² = 40{,}000

Always the same lesson: tightening precision by a factor k costs k² more simulations.

10.5Beyond min/max — combining a full production profile

Not every system-lifetime question is a plain min/max. The oil-production-profile example simulates a multi-phase timeline (delay, ramp-up, plateau, decline) per well, with each phase's duration/rate a random draw (e.g. Beta-distributed), then computes derived quantities like total volume or time-to-threshold-production by piecewise integration of the profile. The general lesson carries over: once you can simulate the pieces, any derived summary is just a function applied to the simulated pieces, then summarized over many replications.

10.6Common exam pitfalls

  • Read carefully whether the system fails at the first failure (series → min) or needs all components to fail (parallel → max) — the two give very different answers.
  • When a component is described as "Exponential" alongside Weibull components sharing the same rate parameter, check whether it's secretly the shape-1 special case before writing a separate simulation routine for it.
  • Sample-size questions here are identical in form to §2.4/§2.5 of the CLT & CIs page — don't re-derive from scratch, just plug into n>4s²/e² or n>1/e².
